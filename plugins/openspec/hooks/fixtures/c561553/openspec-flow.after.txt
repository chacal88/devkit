        with: { node-version: 22 }
      - name: Download the checker (outside the workspace, so no review goes stale)
        run: |
          # pinned to the commit of v0.21.1 (a tag can move; a commit cannot)
          base=https://raw.githubusercontent.com/chacal88/devkit/<commit sha of v0.21.1>/plugins/openspec/hooks
          curl -fsSL "$base/guard.mjs" -o "$RUNNER_TEMP/guard.mjs"
          curl -fsSL "$base/deliver-check.mjs" -o "$RUNNER_TEMP/deliver-check.mjs"
          curl -fsSL "$base/merge-setup.mjs" -o "$RUNNER_TEMP/merge-setup.mjs"

The check also judges the archived folder of a `devkit-project` slice by the slice contract (see "Defining a project"); a project that sets `ship: devkit-project: merge` moves this pin to `v0.20.0` or later first, because older releases pass a slice with a note.

Pin the commit sha of the release tag (`v0.21.1` above), not the tag: a tag can be moved, and this job's output gates the merge. The openspec-setup script resolves the tag to its sha for you (and defers the workflow if the tag does not exist yet); by hand, run `gh api repos/chacal88/devkit/git/ref/tags/v0.21.1` (for an annotated tag, follow `object.sha` through `git/tags/<sha>`). Bump it on purpose. The job id is the check's name (`devkit-reviews`), so give the job no `name:`; and keep the trigger `pull_request` with no `paths:` filter, because a required check that is filtered out never reports. The files are downloaded into `$RUNNER_TEMP`, never into the workspace: a file added to the repository would make every review stale.

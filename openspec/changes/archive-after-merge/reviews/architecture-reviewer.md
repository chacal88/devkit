### Findings
- [important] plugins/openspec/hooks/deliver-check.mjs:748 (`unnamedFiles`, called only at :909) and :1310 (`selectCiChange`) — friction: the "no product file the owner did not approve" rule that ADR 0003 names as the archive PR's gate runs only in the local `deliver-check` run. In CI an archive branch (`chore/archive-<archived id>`) selects no change, so `devkit-reviews` passes with "nothing to check" for a PR that edits product files, and GitHub auto-merges on required checks alone between skill runs. · why: boundary; the gate lives in the session while the merge actuator is server-side, so the ADR's review trigger ("an archive PR merges a file the owner did not approve") cannot be detected by CI. ADR 0003 accepts the missing review, not the missing file check, so this is not an ADR conflict. · direction: run the exact-path check in `runCi` for archive branches (the approved targets are in the committed `retro.md`), so the same `unnamedFiles` serves both consumers; or record in ADR 0003 that the file check is local only.
- [important] plugins/core/skills/retro/SKILL.md:56-100 vs plugins/openspec/hooks/deliver-check.mjs:685 (`readRetro`) — friction: the retro's `## Proposed updates` format is a contract between two plugins (producer in devkit-core, parser in devkit-openspec), and nothing in the tests pins the SKILL's example block against the parser. · why: leverage/boundary; a wording edit to the retro skill silently makes `readRetro` return `readable: false` or no targets, and the run stops at `stop-archive (retro)`. · direction: add a test that extracts the example block from the retro SKILL and asserts `readRetro` parses its three proposals, or move the format into one documented fixture both sides reference.
- [nit] plugins/openspec/hooks/guard.mjs:86, guard.mjs:374, deliver-check.mjs:213, deliver-check.mjs:~745 (`ARCHIVE_NAME`) — the `YYYY-MM-DD-<id>` archive-folder pattern now exists in four places (two new). · why: single owner; guard.mjs already is the shared home deliver-check imports from. · direction: one exported helper in guard.mjs (ids of archived changes, or a name parser) used by all four.
- [nit] plugins/openspec/hooks/deliver-check.mjs (1110 to 1455 lines) — the archive phase (retro parsing, roadmap, GitHub contents reads, `archiveNext`) now shares one file with the eight-item contract. Locality is still good (one file per flow), so not a finding yet; if a round 4 adds more post-merge behavior, consider an archive module that `nextStep` calls through the `state.archive` seam it already has.
- [nit] plugins/openspec/hooks/deliver-check.mjs:1327 / guard.mjs:105 — `chore/archive-<id>` whose `<id>` is both a known change and the tail of a real feature branch named `archive-<id>` would be read as an archive branch; unlikely, and the id must be a known change, so noted only.

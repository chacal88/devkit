### Findings
- [important] `plugins/panel/hooks/report.ts:84` (and `:111`) — friction: both parsers read the `version` field into the view and nothing ever acts on it; `docs/openspec-flow.md:217` and `:292` define `version` as the one compatibility signal of the checkers' JSON ("changes only when a field is removed or changes meaning", v1→v2 of `conduct-check` removed `wake`), so a future version 3 report is drawn silently with fields whose meaning changed, while the tolerant parsing only covers additive changes · why: the devkit-openspec seam is versioned on the producer side and unpinned on the consumer side; the pack is the first external consumer of that contract and sets the precedent for the next one · direction: name the versions the panel reads (2 and 1) in one place and surface a report with a higher version as the header's error line (keep the tolerant parsing for additive fields); pin it with one test per checker.
- [important] `plugins/panel/hooks/register.tsx:68` — friction: the `--change` probe decides `no` by matching the text `unknown option` in a usage error that neither `docs/openspec-flow.md:148` nor `conduct-check.test.mjs:1054` pins (that test asserts only exit 3 for `--bogus`); exit 3 alone is ambiguous (no `openspec/`, an unreadable default branch, a missing `origin/<base>` share it), so the wording is the whole signal · why: coupling across the pack seam to a human message no producer test protects; a rewording in devkit-openspec flips the `Conduct` button to `/conduct` with no test failing on either side · direction: make the reading a contract in the producer: pin the usage-error wording (or a machine field such as `usage: true`) in `conduct-check`'s own test and the flow doc, or let the sibling change expose the accepted options in the JSON so the probe stops spending a whole round computation (with its `gh` calls) on a feature test. Both packs live in this repository, so the cut is cheap.
- [nit] `plugins/panel/hooks/register.tsx:37-69` — friction: the devkit-openspec seam is spread over three files: `project.ts` locates the checker, `register.tsx` builds the argv, sets `DEVKIT_HOST`, the timeout and the probe, `report.ts` parses; design D4 names a `checker.ts#locateChecker` owner while D2's layout puts the location in `project.ts`, and the implementation followed D2 · why: locality; findings 1 and 2 (the version pin, the probe's contract reading) have no single home, and a change to the checkers' CLI touches the composition root · direction: when either lands, give the seam one owner (locate + run + version check), leaving `register.tsx` the refresh ownership of D6 and the hooks; no ADR needed.
- [nit] `plugins/panel/hooks/project.ts:20-21` — friction: the opt-in (`SCHEMA_RE`, `DEVKIT_SCHEMAS`) is a copy of `guard.mjs:130-143`; the cut is impossible (a mod imports only its own files, `reference.md:14`) and D3 says so, and `report.test.tsx:85` pins parity by hand · why: ADR 0004's schema list now lives in two packs; a change to it needs two edits and only a hand-written test notices · direction: let the panel's test read the text of `plugins/openspec/hooks/guard.mjs` from the repository tree and assert the regex and the list are equal, so drift fails a test without a runtime import.
- [nit] `plugins/panel/hooks/project.ts:88` — friction: the pack finds devkit-openspec through the engine's private registry file `~/.claude/plugins/installed_plugins.json` (scope, `projectPath`, `installPath`, `version`), a shape no engine contract documents; the engine's `$` offers no installed-plugin-path API and `dependencies` lays only a `$`-noun contract (`claude-code.d.ts:81-84`), so D2's reasoning stands and the risk register covers a shape change (tolerant reader, `no-checker` line) · why: a seam to an undocumented file; sound today because the repository case (D4 step 1) never touches it and the fallback degrades to one line · direction: record "the engine exposes installed plugin paths on `$`" as the review trigger of this choice (D2 states it only as a rejected alternative), so the registry read is replaced the day the engine owns it.
- [nit] `plugins/panel/hooks/register.tsx:39` — friction: `DEVKIT_HOST: 'app'` is forced on every checker run, so the pack decides the checker's host instead of letting `conduct-check` detect it (`CLAUDE_CODE_ENTRYPOINT`, documented at `docs/openspec-flow.md:292`); a panel loaded by a CLI that runs mods would draw `session` rows the CLI cannot start · why: a small leak of the producer's own concern into the consumer; D4 chose it so the app reads as in `/conduct` · direction: none now (the mod loads in the desktop app only); revisit when the CLI runs mods.

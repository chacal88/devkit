- [nit] `plugins/panel/hooks/register.tsx:223-227` (round 1: `:205-209`) — drifts slightly from ADR 0004 (`docs/adr/0004-devkit-per-project.md`) § Consequences ("projects that did not choose devkit pay no context")
  - What is wrong: the `/devkit-panel` command and the `mcp__devkit-panel__status` tool are registered at `session.start` in every project the mod loads in, so a user-scope install by mistake puts one tool description in the model's context of non-devkit projects (the hooks themselves then do nothing). ADR 0004 governs the devkit-openspec hooks and relies on the per-project install for the rest, which the docs teach, so this is intent, not a violation.
  - Fix: one sentence in `plugins/panel/README.md` "What it never does" (`README.md:47-49`) saying that outside a devkit project the pack still registers the command and the tool (both answer the one line) and that `--scope project` is how a project keeps them out.
- [nit] `openspec/changes/devkit-panel/design.md:361-368` (D16; round 1: `:350-357`) — cite ADR 0001 (`docs/adr/0001-coordination-without-a-harness.md`) § Decision for the human gate the `Approve` button touches

  - Fix: add one sentence to D16 naming the plan-approval gate and that the fill leaves it with the owner.

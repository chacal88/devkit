## Quality review — auto-merge (round 1)

### Findings
- [important] plugins/openspec/hooks/deliver-check.mjs:42-52 (makeGh), :921-933 (waitForMerge) — no `gh` call in the merge path has a timeout. `waitForMerge` checks the deadline only between calls, so one stalled `gh pr view` (network stall, auth prompt) outruns the "capped" wait and the host's 10-minute foreground limit that `WATCH_MAX_MINUTES` exists to respect. The same holds for `mergeSetup`, `collectState` and `github-setup.mjs:39-42` (`runGh`: `spawnSync` with no `timeout`). Only the `wait-checks` watch passes one (:1089). · fix: give `makeGh` and `runGh` a default `timeout` (e.g. 60s) and, inside `waitForMerge`, cap each call at `min(60s, deadline - now)`; treat `timedOut` as "stop waiting", like a gh failure. Add one test with a fake `gh` that hangs.
- [important] plugins/openspec/hooks/deliver-check.mjs:1086-1097 — `nextStep(state)` is called twice in the `--watch` branch (once per `else if`) and recomputed again in `buildReport`; the condition is also evaluated before `state.pr` is guaranteed to carry `autoMerge`. Not a bug today, but the two branches duplicate the same guard. · fix: `const step = state.pr ? nextStep(state).step : null;` once.
- [important] plugins/openspec/skills/openspec-setup/scripts/github-setup.mjs:71 — `discoverContexts` reads `commits/<branch>/check-runs` without `--paginate` or `per_page=100`. GitHub returns 30 by default, so a repository with more check runs gets a silently weaker ruleset (some of its real checks are left out of the required list). It also includes non-CI apps (deploy previews) as required contexts. · fix: `--paginate` (or `per_page=100`) and show the discovered list for the owner's confirmation, which the plan output already half does.
- [important] openspec/changes/auto-merge/ — no `evidence.md`, and tasks 5.1-5.5 are unticked. I ran `node plugins/openspec/hooks/deliver-check.mjs --ci auto-merge` at 55722bf: it reports items 1, 2, 3, 4 open ("evidence.md is missing", "no proof row for AC-1 ... AC-11"). Acceptance criteria therefore have no demonstration with real output; green tests alone are not proof. The plan orders evidence after the reviews (design D11), so this is expected now, but the round cannot be approved until the evidence exists. · fix: after the fixes below, record evidence.md (gates plus one real-output row per AC, including a real `--ci` run and the dogfood run of phase 5) at the new head.
- [nit] plugins/openspec/hooks/merge-setup.mjs:49 — the branch name is interpolated unencoded into `rules/branches/${branch}`. A default branch with `/` or `#` would hit the wrong route; the failure is fail-closed (an error), so it only blocks. · fix: `encodeURIComponent` per segment.
- [nit] plugins/openspec/skills/openspec-setup/templates/devkit-reviews.yml:17-19 — the checker is fetched from a tag (`v{{ref}}`) over curl. A tag moved upstream changes what the required check runs, and the tag must exist before the workflow is merged or the check never reports (the ruleset item defers on exactly this, which is good). The security-reviewer already holds the supply-chain finding; I only note the ordering dependency: tag `v0.5.0` must be pushed before the first PR that carries the workflow.
- [nit] plugins/openspec/hooks/deliver-check.mjs:976-986 — `--ci` with no `openspec/` exits 0 with a note, against design D5. Accepted as the known deliberate deviation (R-3 rationale in the comment). Make sure design.md D5 is amended so the false-claim rule (Phase 1.6) does not apply to the shipped text.
- [praise] plugins/openspec/hooks/merge-setup.mjs:57-71 (`mergeSetup`) — read-only preflight that fails closed on any unreadable answer (missing `gh`, bad JSON, no default branch) and returns a single pointer to the setup skill; classic protection 403/404 is handled as "none" rather than as an error. Constants shared with `github-setup.mjs` live in one module.
- [praise] plugins/openspec/hooks/guard.mjs:392-411 — the dynamic import of `deliver-check.mjs` avoids the import cycle, and only `ERR_MODULE_NOT_FOUND` is turned into the "download all three files" message; any other error still surfaces. The top-level `await` pitfall is documented where it would bite.
- [praise] plugins/openspec/hooks/deliver-check.mjs:709-711 and :924-931 — `disable-auto-merge` outranks every stop step once the contract drops below 8/8, and the merge wait is deadline-based with no unbounded loop (see the first finding for the per-call gap).

Deviations from the text of D-13, each forced by what the first attempts showed:
1. Permissions. The first run without --permission-mode bypassPermissions was denied at its first Bash
   call ("This command requires approval"); D-13 says to run again with bypassPermissions in the
   scratch folder only, which is what both proof runs do.
2. The marker file. The stub's `<root>/.proof-unit-once` is an untracked file in the project root, so
   `flow-check` read "code changed and is not committed" and sent the change back to the implementation
   (a fix-tests hand-off to tdd-implementer) instead of retrying the unit tests. The scratch repository
   lists the marker in `.git/info/exclude`; no stub text changed for this.
3. The stub's "write nothing". `guard.mjs subagent-stop` (U2, refuseOnce) refuses the first stop of a
   stage agent whose stage file does not exist. With the stub as written ("end with Outcome: failure"),
   the Haiku test-runner obeyed the hook, wrote unit-tests.md with result=failed, and the loop answered
   with a fix-tests hand-off, not a retry: the retry rule never ran. Both stubs now say: when a stop hook
   asks for the file, do not write it and stop again at once with the same last line. The two proof runs
   use that text (see the stub bodies below). D-13 should say it in the plan.
   test-runner: "If the file `<root>/.proof-unit-once` does not exist, create it and end with the line
   `Outcome: failure — proof`, and write no file: when a stop hook asks for `unit-tests.md` before you
   stop, do not write it, stop again at once with the same last line (the file must stay absent).
   Otherwise write `unit-tests.md` in the change's folder with the header
   `<!-- devkit-stage unit-tests result=passed attempt=1 commit=<git rev-parse HEAD> -->` on line 1,
   and end with `Outcome: green`."
   e2e-tester: "End with the line `Outcome: failure — proof` and write nothing: when a stop hook asks
   for `e2e-tests.md` before you stop, do not write it, stop again at once with the same last line."

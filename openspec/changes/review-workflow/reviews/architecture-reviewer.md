### Findings
- [important] `review-round.workflow.js:308` and `review-round.mjs:78` (also `:249` `'of 3'`) - friction: the claim "one rules section" is not complete: the verifier count (3), the job construction (`needsVerification` x k=1..3) and the grouping of votes by reviewer and finding sit in the orchestration of the script and again in the CLI, outside the markers; `decide` hardcodes `>= 2` inside the rules. - why: leverage and drift: changing 3 to 5 or the majority is an edit in four places that the section markers do not guard; only the AC-5 parity test (`review-round.test.mjs:587`) catches a miss. - direction: move a `VERIFIERS` constant and a `verifyJobs(args, passed)` (and the votes grouping) into the rules section so both orchestrations call it, and derive `>= 2` and `of N` from it.
- [nit] `plugins/openspec/hooks/guard.mjs:47,230` - friction: `finding-verifier` is not in `REVIEWERS` or any restricted role, so its "writes no file" rests on its tool list and prompt; a shell write from its `Bash` to a non-gate, non-product path (for example `tasks.md`) is not refused. - why: boundary of the one-writer rule; the same weakness does not exist for the six reviewers. - direction: consider a read-only-roles list in the guard in a later change (the design says this change does not touch the guard, so not a rejection).
- [nit] `plugins/core/agents/*-reviewer.md` ("Staged round", six copies) - friction: the same paragraph is repeated in six agents. - why: follows the precedent of the repeated "Verdict file" section, so it passes; but a seventh edit surface exists. - direction: none now; if the stage contract changes, consider pointing the agents to one place.
- [nit] `plugins/core/skills/review-change/scripts/review-round.test.mjs` - friction: core's tests are run only because openspec's `guard.test.mjs:18` imports them; core has no runner of its own for this surface. - why: locality of tests, existing precedent (`openspec-setup/scripts`). - direction: note it in the tasks or the pack README when a core runner appears.

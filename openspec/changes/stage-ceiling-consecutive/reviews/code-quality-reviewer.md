## Quality review — stage-ceiling-consecutive (round 1)

### Findings
- [praise] plugins/openspec/hooks/flow-check.mjs:181-225 (stageHistory, failuresInARow) — The history reader returns [] on every failure and never throws. The count is a pure function that dedupes on `attempt commit` and subtracts no attempt numbers, so the review stage's restarted rounds count right (H-6). With no visible pass the count is max(attempt, failed), so the ceiling is never looser than before.
- [praise] plugins/openspec/hooks/flow-check.mjs:336-339 and :534-538 — History is a lazy, memoised fact (`facts.history`) read only for a failed stage with a numeric ceiling, so `computeFlow` stays pure and a run with no failed stage starts no git process. A facts object with no `history` falls back to today's rule. A spy test pins this.
- [praise] plugins/openspec/hooks/flow-check.test.mjs:2074-2260 — The tests build real git repositories (merges of main, shallow clones at depth 1 and 2, uncommitted takes, no git on PATH). They cover the plan's variants H-3 to H-6 and F-1 to F-4 as well as AC-1 to AC-4, AC-6 and AC-7. The red-before-fix proofs are recorded in proof/red-*.txt.
- [nit] plugins/openspec/hooks/flow-check.mjs:535-537 — For a stage with several files (`specs/**/*.md`, the only multi-file stage, at the default ceiling), the history is read from the first failed file only. A pass recorded in a sibling file is not seen, so the count falls back toward attempt, which is the safe side. D-3 says so, but there is no test for it.
- [nit] plugins/openspec/hooks/flow-check.mjs:186-196 — `git log` has no cap, and `cat-file --batch` reads the whole blob of every commit that touched the file to get its line 1. This is fine for stage files of a few KB. A file with a very long history could hit MAX_BUFFER, and the reader then silently returns [] (today's rule). Optionally stop at the first passed header, or cap the log with -n.
- [nit] plugins/openspec/hooks/flow-check.mjs:337 — `join(relative(root, located.dir), path)` produces backslashes on Windows, and the later `<sha>:./<rel>` lookup would then miss the file and return [] (today's rule). Acceptable for the supported platforms. Optionally normalise to '/'.
- [nit] plugins/openspec/hooks/flow-check.mjs:219-224 — A failed take overwritten without a commit after a visible pass lowers the count, so the ceiling is looser than today in that case (H-5). The plan accepts it and docs/openspec-flow.md says 'commit each take'. It is worth watching in the field.
- [nit] plugins/openspec/hooks/change-loop.mjs:798 — The `failures` placeholder falls back to the attempt (`params.failures ?? need('attempt')`), so a blocked end recorded before this release still renders. The fallback and its two language lines are tested.
- [praise] openspec/changes/stage-ceiling-consecutive/evidence.md — Every AC carries real command output (flow-check --json, change-loop next in en and pt-BR, a depth-1 clone) re-run at the merged head. The one AC with no proof (AC-8, ticked at archive) says why.

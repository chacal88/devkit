## Quality review — roadmap-sessions-upfront (round 1)

### Findings
- [important] plugins/openspec/hooks/roadmap-loop.mjs:900 (unpushedOf), :885 (filesPushed) — unpushedOf returns 'plan' whenever approval.md passed and any PLAN_FILES path is dirty or ahead of origin, with no stage guard. While the implementer ticks tasks.md the push stays due on every decision, so a half-ticked tasks.md is committed as 'docs(openspec): plan of <id>', and the coordinator's git add/commit can race the change session's own git. Fix: return 'plan' only while no later stage has started (or push 'plan' only when the committed tasks.md differs, ignoring ticks) and add a test with a dirty tasks.md after approval.
- [important] plugins/openspec/hooks/guard.mjs:950-955 (skillEntry) — The fail-closed catch also wraps `await import('./roadmap-loop.mjs')`. A module that cannot load refuses every Skill call of every project with the plugin, which contradicts the spec scenario 'Another skill: this rule lets the call through'. Every Skill call also pays the full import before the not-entry check, and the mode skips the opt-in gate the lock modes use. Fix: test cheaply in guard.mjs whether any tool_input string names devkit-session and return before the import; fail closed only for the import when it is named.
- [important] plugins/openspec/hooks/roadmap-loop.mjs:932 (killWaits), :1396 (checkCmd watchAlive) — killWaits sends SIGTERM to a pid read from the run file, and checkCmd counts a pid as alive with kill(pid, 0), with no check that the pid is still the wait loop that wrote it. After a reboot or a long run the pid can belong to an unrelated process of the owner. The tests never send a signal. Fix: record the process start time with the pid, or check the command line (`ps -o command= -p <pid>` contains roadmap-loop.mjs and wait) before signalling, and add a test with a recycled pid.
- [nit] plugins/openspec/hooks/change-loop.mjs:961-1011 — The header comment of `decide` ('facts: { ctx ... } Returns the action ... pure') is now separated from `export function decide` by the triage section (lines 967 to 1010). Move the triage block above that comment.
- [praise] plugins/openspec/hooks/roadmap-loop.mjs:393 (placeDecision, sessionDecide) — The one place rule is a pure function that returns new records and is re-decided on the run file under its lock, so the places stay consistent under concurrent sessions. It is also the single reader that the check, session-next and session-wait share.
- [praise] plugins/openspec/hooks/roadmap-loop.mjs:634 (entryDecision) and roadmap-loop.test.mjs:2860 — The ticket claim is re-checked under the run file's lock, and the refusal always names the owner's typed fallback. Tests cover each label plus the guard exit codes, the DEVKIT_HOOK_LOG line, the bypass and the other-skill path.
- [nit] plugins/openspec/hooks/roadmap-loop.mjs mergeBaseCmd (the catch around git merge) — Every failure of `git merge` (a dirty tracked file that refuses the merge, for example) is reported as why=base-conflict with the text 'could not be merged'. Only a real conflict deserves that label; consider checking for unmerged paths before labelling.

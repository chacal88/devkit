## Architecture review — conduct-rounds (12aa99e..8f6f2bd), round 1

Analyzed: owners (approval state -> deliver-check `approvalState`; release-file list -> deliver-check `RELEASE_FILE`; gate-file writers -> guard `classify`; roadmap parse -> guard `parseRoadmap`); boundaries (conduct-check -> deliver-check, release-rebase -> deliver-check, conduct skill -> ship-change skill, guard root resolution per target); contract consumers enumerated (deliver-check JSON `next.step`/`approval`/exit code: ship-change SKILL row and report line, conduct-check `deliveryStep`/`actorOf`, deliver-check tests; `readRoadmap` -> `parseRoadmap` callers; `classify` callers guard.mjs:217/345); deletion tests (conduct-check.mjs: passes, it owns the cross-change round computation that deliver-check by design does not know; release-rebase.mjs: passes, a deterministic rebase+renumber rule a skill prompt cannot do reliably, and a separate CLI the checker only names in `command`).

### Good points
- The approval check has one owner. `approvalState` lives in deliver-check.mjs:944 and conduct-check reuses it (conduct-check.mjs:13, planFacts `approval: approvalState(dir)`), so `/ship-change` and `/conduct` cannot disagree on what "approved" means. Same for `RELEASE_FILE` (deliver-check.mjs:755, imported at release-rebase.mjs:14): the list was cut and exported, not copied.
- `approval.md` as a main-session-only gate (guard.mjs:208, :220-223) reuses the existing `classify`/`writeViolation` seam instead of inventing a second mechanism, and the hash binding to `readiness.md` makes a new readiness round invalidate it with no extra state.
- Hooks now resolve the root from the target path (guard.mjs:338, guardBash per-target roots), the correct seam for worktrees; `commandSegments` is extracted and shared by `bashWrites` and the `gh pr create` check (cut, not copy).
- The structural decision (parallel steps plus cron) is recorded as ADR 0005, with a pointer in ADR 0001.

### Findings
- [important] plugins/openspec/hooks/conduct-check.mjs:375-376 — friction: conflict detection matches deliver-check's human `reason` with `/has merge conflicts/` plus `n.item === 5` / `archiveStep`. The contract between the two checkers is a prose string (emitted at deliver-check.mjs:517 and :910). · why: seam leak; reword the message and conduct silently stops recognizing conflicts (falls to a plain `blocked`), and no test ties the two. · direction: have deliver-check emit a structured field (for example `conflict: true` on item 5 and on the archive stop) and read that.
- [important] plugins/openspec/hooks/conduct-check.mjs:346-358, :387-398 — friction: overrides read `collectState` internals (`state.archive.pr`, `state.pr.headRefOid`, `state.dirty`, `state.branch`, `state.ship`), not the report JSON that is the published contract. · why: a refactor of deliver-check's internal state shape breaks conduct with no consumer enumeration pointing at it. · direction: surface the few facts needed in the report (head OID, branch, dirty paths), or declare `collectState` a supported interface and pin it with a test.
- [important] plugins/openspec/hooks/conduct-check.mjs:55-70 — friction: `actorOf` is a second hand-written registry of deliver-check's step names, and an unknown step falls to `{ actor: 'none' }`, which is neither runnable, owner, github nor stopped, so a new deliver-check step makes the change drop out of `dispatch` and `stopped` instead of stopping loudly. The test at conduct-check.test.mjs:508 is a hand-listed table, not derived from deliver-check. · why: leverage runs the wrong way (one deliver-check change needs a second edit, and forgetting it is silent). · direction: default unknown steps to `stop` ("unmapped step <x>"), and make the test enumerate the steps deliver-check can emit.
- [important] plugins/openspec/hooks/conduct-check.mjs:24-30, :507-513 — friction: `git`/`gitOk`, `pollSeconds` and `sleepSync` are copies of deliver-check.mjs:137-146 and :1287-1294 (only the default 60 vs 30 and stdio differ); release-rebase.mjs:124-137 adds a third git wrapper. · why: cut-not-copy; three variants of the same helper, and the watch loop (:559-575) mirrors `waitForMerge`. · direction: export the helpers from one home (deliver-check already exports `makeGh` that way) or a small shared module, parameterizing the default.
- [nit] plugins/openspec/hooks/release-rebase.mjs:14 — importing the 1500-line deliver-check (and its gh stack) only for one regex couples a standalone CLI to the delivery checker. Acceptable now; if a third consumer of `RELEASE_FILE` appears, give it a leaf home.
- [nit] plugins/openspec/hooks/guard.mjs:220-223 and plugins/openspec/skills/ship-change/SKILL.md (Go-ahead) — the "owner's own message" rule for `approval.md` is honor-system: the hook only separates main session from subagents, and the hash is computable by anyone. This matches the retro-answers precedent and D7 chose it, so not a defect; keep the limit stated in the docs.
- [nit] plugins/openspec/skills/conduct/SKILL.md (Planning rows, `approve`) vs ship-change `stop-plan-approval`: two step names for one gate, deliberately (D7/P-5, planning runs before delivery). The skill delegates the form by reference, which is the right boundary; keep the two rows in step.
